# Контекстная параметризация модели привода для sim-to-real

> Исследовательский проект: физически информированная параметризация модели привода антропоморфного робота для повышения адекватности имитационного моделирования.
>
> *English:* a research project on context-dependent parameters of a humanoid joint actuator model. Measure the actuator on a test bench, find how friction, backlash and hysteresis change with load, temperature, speed and wear, build a model of these dependencies, and check whether it reduces the torque error in simulation compared with fixed parameters and domain randomization. ROS 2 is used only in the part of the project that needs it (HIL and shadow mode).

**Стадия проекта:** проектирование эксперимента. Протокол и дизайн эксперимента готовы, пилотные измерения ещё не проведены, код в репозитории появляется по мере выполнения этапов.

---

## В чём идея

Политики управления роботом (RL) обучают в симуляторе, а затем переносят на реальное железо. Разрыв между симуляцией и реальностью в значительной степени возникает в приводах: в симуляторе параметры привода обычно постоянны, а в реальности трение, люфт и гистерезис нелинейны и меняются со скоростью, нагрузкой, температурой и износом. Из-за этого модель неточно воспроизводит момент, политика теряет устойчивость и даёт фазовый сдвиг на реальном роботе. Индустриальное требование — погрешность момента менее 5 %.

Существующие подходы либо идентифицируют **фиксированные** параметры для конкретного экземпляра привода, либо **рандомизируют** их в эвристических диапазонах (domain randomization), либо строят нейросетевой суррогат момента. Закономерности изменения параметров в зависимости от контекста эксплуатации при этом не устанавливаются и не формализуются.

**Идея проекта:** измерить привод на стенде, выявить, как его параметры зависят от контекста эксплуатации, описать эти зависимости математической моделью и проверить, повышает ли это адекватность симуляции.

> Основа работы — поиск закономерностей и их математическая модель. Нейросеть вспомогательная: она аппроксимирует остаточную зависимость там, где параметрической формы недостаточно.

## Гипотеза и способ проверки

**H1.** Физически обусловленная параметризация нелинейных потерь привода, идентифицированная на ограниченном наборе режимов, уменьшает ошибку оценки входного момента двигателя на независимых скоростных, реверсивных и температурных режимах по сравнению с фиксированными параметрами и с domain randomization (рандомизация параметров в пределах ±30 % от изначальных значений).

| Элемент | Решение |
|---|---|
| Первичная метрика | RMSE момента привода (модель против стенда) на режимах вне идентификации, Н·м и % номинального момента |
| Порог | снижение RMSE не менее 10 % относительно лучшей из моделей сравнения; инженерный допуск ≤ 5 % номинального |
| Модели сравнения | фиксированные параметры (единый набор по обучающим режимам); domain randomization ±30 % от изначальных значений |
| Эталон «реального» момента | тензометрический датчик момента на выходном валу; оценка по току используется только после сверки с эталоном |
| Дизайн | факторный план: масса нагрузки (3 уровня) × тепловое состояние (3 уровня), скорость сеткой внутри испытания; SIL → физический стенд, повтор на втором идентичном экземпляре привода |
| Объём | 9 условий × 15 повторов = 135 испытаний на первом экземпляре и 18 на втором (≈ 16 ч стенда); повторы уточняются по пилоту |

Подробности: `docs/protocol.md` и `docs/design-of-experiment.md` (будут добавлены).

## Из чего состоит проект

Проект разделён на слои. Каждый слой работает без следующего, поэтому стенд и анализ данных не зависят от ROS 2.

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Стенд и машина записи   (без ROS 2)                      │
│    привод BLDC + редуктор, плечо с грузом, эталонный датчик │
│    момента, температуры, энкодер, ток; микроконтроллер      │
│    ставит метки времени; запись на ПК в CSV                  │
├─────────────────────────────────────────────────────────────┤
│ 2. Идентификация и модель   (Python, без ROS 2)             │
│    параметры привода, зависимости от контекста,             │
│    математическая модель, сравнение с baseline              │
├─────────────────────────────────────────────────────────────┤
│ 3. Симуляция   (MuJoCo, Isaac Sim / Isaac Lab, без ROS 2)   │
│    встраивание модели привода, обучение и оценка политики   │
├─────────────────────────────────────────────────────────────┤
│ 4. ROS 2 — только здесь                                     │
│    HIL и shadow mode, мост к Isaac Sim, драйвер привода,    │
│    при необходимости воспроизведение записей через rosbag2  │
└─────────────────────────────────────────────────────────────┘
```

### Слой 1. Стенд и машина записи

| Сигнал | Источник | Частота |
|---|---|---|
| Момент (эталон) | датчик момента на выходном валу, АЦП не медленнее 1 кГц | 1000 Гц |
| Момент (косвенно) | датчик тока ACS724 | 1000 Гц |
| Положение и скорость | абсолютный энкодер AS5600 | 1000 Гц |
| Температура мотора и корпуса редуктора | два датчика PT100 | 1 Гц |
| Температура окружающей среды | DS18B20 | 1 Гц |
| Время | часы реального времени, общая метка времени для всех каналов | — |

Принципы: метки времени ставит микроконтроллер в момент измерения; сырые данные хранятся отдельно от обработанных; для каждого испытания ведётся паспорт (номер, версия протокола и ПО, конфигурация, условия, события, статус «валидно / исключено»).

### Слой 4. Где используется ROS 2 и почему только там

ROS 2 добавляется **только** в тех частях, где он даёт реальную выгоду:

- **HIL и shadow mode.** Мост ROS 2 нужен для связи Isaac Sim с реальным контуром управления.
- **Драйвер привода.** Если для выбранного привода есть готовый узел ROS 2, его проще использовать, чем писать свой.
- **Воспроизведение записей.** rosbag2 допустим как дополнительный формат для повторного проигрывания, основной формат стенда остаётся CSV с метками времени.

В измерительном контуре ROS 2 **не используется**. На обычной Linux-системе он не гарантирует реальное время, а метки времени при приёме сообщения имеют джиттер порядка миллисекунд. Для сигналов на 1 кГц это даёт ошибку фазы между током, положением и моментом, что критично для реверсов и измерения люфта. Поэтому измерительные этапы 1–2 выполняются без ROS 2, а он подключается отдельным слоем, когда проект доходит до HIL и shadow mode. Дистрибутив ROS 2 фиксируется на этом шаге с учётом совместимости с используемой версией Isaac Sim.

## Воспроизводимость

- Протокол версионируется с датой; изменить можно, скрыть изменение нельзя (журнал изменений).
- Критерии, пороги и метод анализа фиксируются до эксперимента.
- Пилотный запуск обязателен: он проверяет стенд, запись, синхронизацию, частоту дискретизации и даёт оценку разброса для расчёта числа повторов.
- Все запуски сохраняются, включая неудачные; исключение испытания помечается причиной.

## Ограничения применимости

Результат относится к классу высокоредукторных приводов (BLDC-мотор с планетарным или цевочно-циклоидным редуктором) в исследованных диапазонах нагрузки, температуры, скорости и наработки. Износ оценивается по числу циклов и времени работы, ускоренные испытания не равны износу в эксплуатации. Перенос RL-политики на робота проверяется в HIL и shadow mode и без этого не заявляется.
